# Day 102: Saving Student Progress (Microservices)

## 1. The Milestone
Implement data persistence by having the FastAPI AI service send the evaluation results to the Django PostgreSQL backend using a background task.

## 2. The Architecture (Why)
In our Option B (Microservices) architecture, FastAPI does not connect to the database. Instead, it acts as a client. 
When a student submits an essay:
1. FastAPI calls Claude to generate feedback.
2. FastAPI returns the feedback to the student immediately.
3. FastAPI triggers a **BackgroundTask** to POST the results to the Django API (`/api/v1/progress/save/`).

This keeps the user experience fast while ensuring the database stays perfectly synced.

## 3. The Implementation (How)
- We will add a `save_progress_to_django` function that uses `httpx` to make an asynchronous POST request.
- We will attach this to the `/feedback` route using FastAPI's `BackgroundTasks`.
- Because we don't have the Django server running in Colab, we will use a mock URL and test it locally.

## 5. Key Takeaways
- **BackgroundTasks:** The difference between a slow app and a fast app is often just moving database writes out of the main request thread.
- **Microservices:** By forcing API-to-API communication, we ensure Django remains the single source of truth for user data.
