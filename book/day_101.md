# Day 101: Transitioning to JWT Authentication

## 1. The Milestone
Replace the static API key with JSON Web Token (JWT) authentication to support multi-tenancy, while maintaining a fallback for CI/CD automation.

## 2. The Architecture (Why)
A static API key means every user shares the same identity. By switching to JWTs, the Django backend can issue a token to a specific student. When the student uses the React app, it sends this token to FastAPI. FastAPI decodes it, extracts the `user_id`, and can track rate limits and token budgets per student, not per app.
We are using a microservices pattern (Option B): FastAPI does NOT touch the PostgreSQL database. It only validates the JWT signature using a shared secret.

## 3. The Implementation (How)
- Added `python-jose[cryptography]` to requirements.
- We will implement a FastAPI dependency `get_current_user` that checks the `Authorization: Bearer <token>` header.
- If the JWT is invalid or missing, it falls back to checking the `X-API-Key` header (so our CI/CD gate continues to work).

## 4. The Debugging Diary
*   **The initial attempt:** We wrote the JWT verification logic and deployed it. 
*   **The test:** We generated a valid JWT using the shared `dummy_jwt_secret_for_ci_pipeline`. We hit the `/feedback` endpoint and received a `200 OK`. 
*   **The security check:** We generated a token signed with a *wrong* secret (`WRONG_SECRET`). FastAPI correctly rejected it with a `401 Unauthorized`. 
*   **The CI check:** We sent a request using the old `X-API-Key` header. FastAPI's fallback logic accepted it, proving our CI/CD pipeline won't break.

## 5. Key Takeaways
- **Stateless Auth:** FastAPI doesn't need to query a database to verify the user; it just verifies the JWT signature.
- **Graceful Fallbacks:** By keeping the API Key fallback, we can transition the frontend to JWT without breaking our existing CI/CD gate.
- **Cryptographic Security:** A JWT signed with the wrong secret is mathematically rejected, preventing identity spoofing.
- JWTs allow stateless authentication. FastAPI doesn't need to query the database on every request; it just verifies the cryptographic signature.
