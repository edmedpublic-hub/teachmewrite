# Day 101: Transitioning to JWT Authentication

## 1. The Milestone
Replace the static API key with JSON Web Token (JWT) authentication to support multi-tenancy, while maintaining a fallback for CI/CD automation.

## 2. The Architecture (Why)
A static API key means every user shares the same identity. By switching to JWTs, the Django backend can issue a token to a specific student. When the student uses the React app, it sends this token to FastAPI. FastAPI decodes it, extracts the `user_id`, and can track rate limits and token budgets per student, not per app. 
We are using a microservices pattern (Option B): FastAPI does NOT touch the PostgreSQL database. It only validates the JWT signature using a shared secret.

## 3. The Implementation (How)
- Added `python-jose[cryptography]` to requirements.
- We will implement a FastAPI dependency `get_current_user` that checks the `Authorization: Bearer <token>` header.
- If the JWT is invalid or missing, it falls back to checking the `X-API-Key` header (so our CI/CD gate continues to work).
