## 2. The Architecture (Why)

### The three pillars
- **Pillar 1 (Auth):** Django `simplejwt` signs JWTs with `settings.SECRET_KEY`. Frontend stores `access` + `refresh` in localStorage. All API calls carry `Authorization: Bearer <jwt>`.
- **Pillar 2 (AI Feedback):** FastAPI on Cloud Run decodes the JWT, calls Claude Haiku with a level-aware prompt, returns structured JSON.
- **Pillar 3 (Progress persistence):** FastAPI BackgroundTasks POSTs feedback back to Django. **Not wired today** — Django has no callback endpoint. Deferred to Day 106+.

### The three deploy fixes (all needed, none sufficient alone)
1. **CORS middleware on FastAPI.** Without it, browser preflight received no `Access-Control-Allow-Origin`, request aborted before reaching `/feedback`. Fix: `CORSMiddleware` with `allow_origin_regex` for `*.loca.lt` and (later) `*.trycloudflare.com`.
2. **JWT secret sync on Cloud Run.** FastAPI's `JWT_SECRET_KEY` defaulted to `dummy_jwt_secret_for_ci_pipeline`; Django signed with `django-insecure-dev-only-change-in-production`. Every real token would 401. Fix: `deploy.yml` line 59 sets `JWT_SECRET_KEY` explicitly. **Day 106 TODO: rotate both to Secret Manager-backed strong key.**
3. **httpbin stop.** FastAPI's `DJANGO_API_URL` default was `https://httpbin.org/post`. Every `/feedback` call was POSTing the full `student_text` to a third-party server. The try/except logged "success" (httpbin returns 200). Silent exfiltration. Fix: `DJANGO_API_URL=http://127.0.0.1:1/disabled` — loopback refuses immediately, task fails safely, student text stays inside Cloud Run.

### Why cloudflared instead of localtunnel
`localtunnel` (`*.loca.lt`) returned 511 (Network Authentication Required) on the app URL and 503 (Service Unavailable) on `/mytunnelpassword` mid-session. Both paths down. Pivoted to `cloudflared` quick tunnel (`*.trycloudflare.com`) — free, no account, no password page. ~15 min cost, 2 config edits. Lesson: tunnel provider availability is third-party infrastructure; always have a second one ready.

## 4. The Debugging Diary (Exact errors and fixes)

Ten entries, ordered by when they surfaced. Not all are bugs — some are process learnings that cost cells.

**Entry 1 — Fixed-width slice ate the leading dot (Cell 17)**
- Symptom: `RuntimeError: Unexpected modified files: {'github/workflows/deploy.yml'}`
- Cause: pre-flight parsed `git status --porcelain` with `ln[3:]`, assuming fixed 3-char prefix. Two-char prefixes (` M path`) caused path slice to consume the leading `.`.
- Fix: `git diff --name-only HEAD` + `git ls-files --others --exclude-standard` — clean paths, no prefix parsing.

**Entry 2 — Missing syntax verification after edit (Cell 14 -> Cell 15)**
- Symptom: none, because check did not exist.
- Cause: Cell 14 asserts verified insert happened but not that file still parsed. If f-string regex mis-escaped, deploy would fail with obscure import error, not at edit time.
- Fix: Cell 15 added `ast.parse(main.py)`. **Every file-edit cell must end with a syntax check.**

**Entry 3 — Dropped `npm install` during cell decomposition (Cell 20)**
- Symptom: `RuntimeError: build failed rc=127 sh: 1: vite: not found`
- Cause: initial Day 105 plan bundled clone + pip + npm install. Splitting the cell for one-concern-per-cell dropped the npm branch. `node_modules` is gitignored, so fresh clone has no vite binary.
- Fix: Cell 20b — `npm install`, 7.9s. **Lesson: when splitting a bundled cell, write down every step, verify each has a home.**

**Entry 4 — `git commit` exit 128: identity unknown (Cell 20e -> 20e2)**
- Symptom: `CalledProcessError` with exit 128 and no useful stderr (because `subprocess.run` swallowed it).
- Cause: `git config user.email/user.name` set in Day 104 was repo-local (`.git/config`). Today's fresh clone has no identity.
- Fix: Cell 20e2 sets identity if missing. **Every commit-carrying cell must set identity idempotently. Never use `check=True` alone when the error message is the debugging data you need.**

**Entry 5 — Stale pre-flight expectation (Cell 20e2 -> 20e3)**
- Symptom: `AssertionError: Unexpected working-tree state: ['ai-service/main.py', 'frontend/package-lock.json', 'frontend/vite.config.js']`
- Cause: pre-flight asserted `mod == ["ai-service/main.py"]`, but Cell 20d intentionally modified `vite.config.js` and Cell 20b's npm install drifted `package-lock.json`. Mental model of "what is modified" was stale.
- Fix: Cell 20e3 restored `package-lock.json` to HEAD, committed both intended files. **When asserting expected files, list every file any cell has touched since last commit — not just the one this cell edits.**

**Entry 6 — Empty database on fresh clone (Cell 21a-diag)**
- Symptom: login 500 (`OperationalError: no such table: auth_user`). DB file exists, 0 bytes.
- Cause: `backend/db.sqlite3` committed as empty placeholder. Migrations never run.
- Fix: `python manage.py migrate` — 31 tables. **"Django UP" only proves port is open. Stronger check: `showmigrations --plan`.**

**Entry 7 — Seed script missing `models` import (Cell 21a-seed -> 21a-seed-fix)**
- Symptom: `NameError: name 'models' is not defined` at seed line 135.
- Cause: seed uses `models.Max('order')` but only imports `from lessons.models import ...`. `django.db.models` never imported.
- Fix: added `from django.db import models` at line 5. **Real repo bug — seed has been broken since written.** Day 106 TODO: audit for other missing imports, no other missing-import sites found in this pass.

**Entry 8 — Seed script does not create demo users (Cell 21a-seed-fix -> 21a-users)**
- Symptom: seed returns rc=0, but `auth_user` count = 0.
- Cause: `seed_learning_data.py` only seeds Unit/Lesson/LessonUnit/QuestionBank. Users must be created separately. Landing page advertises `student_basic / testpass123` but those users were never seeded.
- Fix: Cell 21a-users — Django shell creates 4 demo users with `set_password`. 4 users, all active, direct login 200.
- Finding: `User` model has no `tier` field. Navbar reads `user?.tier || 'BASIC'`, so all 4 demo users display "BASIC" until tier linked via Profile/Group/enrollment. **Day 106 TODO: locate tier relationship, fix seed to set it.**

**Entry 9 — localtunnel 511 + 503 (Cell 20 -> Cell 20c)**
- Symptom: 511 on app URL, 503 on `https://loca.lt/mytunnelpassword`.
- Cause: localtunnel public service outage mid-session. Both app path and password workaround down.
- Fix: pivoted to `cloudflared` quick tunnel. ~15 min, 2 config edits. **Tunnel providers are third-party infra — always have a second in the runbook.**

**Entry 10 — Expected-output block pasted as code (twice)**
- Symptom: `SyntaxError: invalid character '—' (U+2014)` on a line like `[push] OK — deploy pipeline triggered`, and `SyntaxError: invalid syntax` on `=== (1) python manage.py migrate ===`.
- Cause: cell messages put code and expected-output both inside triple-backtick blocks. Wrong block pasted twice.
- Fix: from Day 106 onward, every code block starts with `# === CELL <id>` as first line. Every expected-output block is prose description, not fenced code. **Eliminate layout ambiguity at the source, not through user cautions.**

## 5. Key Takeaways

**5.1 — E2E is empirical, not inferential.** The code looked correct in Cell 9. Deploy succeeded in Cell 18. Cell 19's fake-JWT test proved CORS + auth rejection. **None proved E2E.** Only CP4 — a real essay from a real browser — proved it. If we had stopped at "deploy succeeded," the chapter would have been plausible fiction.

**5.2 — Three fixes were needed, in order, none obvious before the previous was live.** CORS blocked the request before FastAPI. JWT sync blocked it at FastAPI's auth layer. httpbin exfiltration was silent — never blocked E2E. **The path to E2E was a chain, not a list.**

**5.3 — The httpbin finding is governance, not a bug fix.** Every `/feedback` call since AI-service deployment POSTed student essays to `https://httpbin.org/post`. The try/except logged "success" (httpbin returns 200). **Silent exfiltration through a "safe" default is the worst class of security bug: doesn't fail, doesn't alert, works as designed.** Day 106 TODO: audit all env-var defaults for third-party URLs.

**5.4 — Documentation promised what implementation did not deliver.** The landing page has advertised demo credentials since Phase 2 started. The seed script has never created those users. Day 106 TODO: either extend the seed to create them, or remove the credentials from the landing page. (a) is better — demo accounts are a real feature.

**5.5 — Book chapters need artifacts, not prose.** This chapter would be worthless without the fact that score 88/100 rendered at a public URL. Debugging entries are specific (file, line, error, fix), not vague. **A chapter that could have been written without having done the work is a chapter that adds no value.**

**5.6 — Phase 2 is not "starting" — it is substantially complete.** Teacher dashboard, mastery reports, certificates, adaptive endpoints all exist. The gap is **integration**, not construction. Days 106–120 should be integration + polish + demo-account realism, not new features. That is a better roadmap than the context file assumed.
