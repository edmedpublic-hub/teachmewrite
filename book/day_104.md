# Day 104: Visual Verification & Full-Stack Integration

## 1. The Milestone
Serve the React application and Django backend locally in Colab, expose them via a public tunnel, and successfully render the frontend.

## 2. The Architecture (Why)
Because Colab runs in a headless cloud environment, we used `localtunnel` to route external traffic to the Vite preview server. We also had to configure Vite's proxy to forward `/teach-me-write/api` requests to the Django backend running on port 8000.

## 3. The Implementation (How)
- Installed `localtunnel` via npm.
- Fixed the Django `requirements.txt` encoding from UTF-16 (Windows BOM) to UTF-8.
- Ran `python manage.py migrate`.
- Updated `vite.config.js` with a proxy to Django and set `allowedHosts: true`.
- Used `npm run build` and `npm run preview` for stability.

## 4. The Debugging Diary
*   **The 501 Error:** The frontend returned a `501 Not Implemented` when trying to log in. Cause: `python3 -m http.server` cannot handle POST requests. Fix: Switched to `npm run preview` with a Vite proxy.
*   **The UTF-16 Crash:** Reading `backend/requirements.txt` caused a `UnicodeDecodeError`. Cause: File saved in UTF-16 encoding. Fix: Converted to UTF-8 via Python.
*   **The Colab Disconnect:** Using `subprocess.PIPE` for long-running servers crashed the Colab runtime. Fix: Redirected server logs to files (`vite.log`, `tunnel.log`).
*   **The 404 Tunnel Error:** Vite built the app with a base path of `/teach-me-write/`, causing localtunnel 404s. Fix: Cleaned the `dist` folder and let Vite handle the base path automatically.

## 5. Key Takeaways
- **Dev vs. Prod:** Production builds (`npm run build`) are much more stable for tunneling than dev servers.
- **Proxies:** Vite's built-in proxy is the correct way to connect a React frontend to a Django backend in local development.
- **Encoding Matters:** Always enforce UTF-8 in Python projects to avoid cross-platform bugs.
